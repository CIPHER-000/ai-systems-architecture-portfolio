Architecture Overview

ChessRun uses a layered intelligence architecture that separates engine analysis (Stockfish) from pattern recognition and AI coaching. This enables reusability of Stockfish analysis for pattern detection, scalable pattern computation across large game histories, and context-aware AI coaching that synthesizes multiple data sources.

1.1 Stack

FrontendNext.js (React, TypeScript), React Query, Axios, TailwindCSS — AI Coach chat, pattern visualization, interactive training board

PGN + Stockfish Analysis Pipeline

4.1 Overview

Pipeline executed by the Celery worker, once per game:

  1. Load games.pgn
  2. Parse PGN into move list using python-chess
  3. For each position before a move: evaluate with Stockfish, determine best move, compute eval delta
  4. Classify move quality (good/inaccuracy/mistake/blunder)
  5. Aggregate stats per game and by phase
  6. Store results in game_analyses; mark game is_analyzed = true

4.2 Detailed Steps

4.2.1 PGN Parsing

  • Use chess.pgn.read_game() to read PGN from text.
  • Iterate the mainline moves, capturing the position before and after each one:
python
import chess, chess.pgn

game = chess.pgn.read_game(io.StringIO(pgn_text))
board = game.board()

for move_number, move in enumerate(game.mainline_moves(), start=1):
    fen_before = board.fen()
    board.push(move)
    fen_after = board.fen()
    # Store fen_before, fen_after, move SAN/uci, etc.

4.2.2 Engine Evaluation

  • Wrap Stockfish with the python-chess engine API or a direct UCI wrapper.
  • For each fen_before:
python
with chess.engine.SimpleEngine.popen_uci([settings.STOCKFISH_PATH]) as engine:
    engine.configure({"Threads": 2, "Hash": 128})
    info = engine.analyse(board, limit=chess.engine.Limit(depth=settings.STOCKFISH_DEPTH))
    score = info["score"].pov(board.turn)
    best_move = info.get("pv", [None])[0]
  • Convert score to centipawns; handle mate scores explicitly rather than leaving them unbounded.

4.2.3 Move Quality Classification

ClassificationCentipawn loss
Bestthe engine's own choice, or no measurable loss
Excellent≤ 25 cp
Good≤ 50 cp
Inaccuracy> 50 cp
Mistake> 100 cp
Blunder> 300 cp, or a lost forced mate

The loss for a move is cp_loss = max(0, eval_before − eval_after), measured in the mover's own frame: eval_before is the evaluation of the position the mover was facing.

Why the frame matters. Score.pov(board.turn) is relative to the side to move, so the frame alternates every ply: the evaluation taken after a move is the opponent's view. Comparing two consecutive evaluations without converting them therefore reads a stable advantage as a large loss — a level position that nobody is losing can look like a blunder on every ply. The loss is clamped at zero because a move that improves the evaluation cannot be a loss, and mate scores are bounded rather than left unbounded so a single decisive position cannot swamp an average.

Comparing the played move against the best move (eval_before(best) − eval_before(played)) remains an open refinement; the shipped metric is the eval drop attributable to the move itself.

4.2.4 ACPL & Accuracy

  • ACPL = mean of cp_loss over the user's moves — clamped at zero, in the mover's own frame
  • Accuracy mapping (piecewise linear): ACPL <10 → 99 · 10–20 → 95–99 · 20–50 → 80–95 · 50–100 → 60–80 · ≥100 → ≤60
  • Provenance: the same per-move loss is persisted to the move-facts layer, so every average the coach quotes can be traced back to the engine evaluation of one move

4.2.5 Phase-Based Metrics

  • Opening: moves 1–12
  • Middlegame: moves 13–30
  • Endgame: moves >30 or when material is sufficiently reduced

Per phase, compute:

  • phase_acpl
  • phase_blunders, phase_mistakes, phase_inaccuracies
  • A 0–100 phase score, using the same mapping as the overall accuracy score

Game Fetching & Caching

5.1 Chess.com Fetch Strategy

  • Endpoint: https://api.chess.com/pub/player/{username}/games/{YYYY}/{MM}
  • Determine which months to inspect from the date range and the desired game_count
  • Fetch in reverse chronological order until N games collected or date range exhausted

5.2 Caching Layer (Redis)

  • chesscom:archives:{username}:{year}:{month} → archived JSON/PGN (TTL 1h)
  • chesscom:rate:{username} → request counter per minute
  • If the rate key exceeds the threshold, abort with a 429-style error before any external call
  • On fetch: check rate key → check archive key → call Chess.com → cache result

5.3 Replace-All Semantics

  1. Start DB transaction
  2. Delete game_analyses for user_id
  3. Delete games for user_id
  4. Insert fetched games
  5. Update users.total_games and users.last_fetch_at
  6. Commit

This avoids complex deduping at the cost of an analysis reset, which is aligned with the current product decision.

Tactical Pattern Detector

class TacticalPatternDetector:
    def detect(self, user_analyses: List[GameAnalysis]) -> List[Pattern]:
        patterns = []
        theme_counts = defaultdict(list)

        for analysis in user_analyses:
            for moment in analysis.critical_moments:
                if moment.error_type in ['blunder', 'mistake']:
                    theme = self.classify_tactical_theme(moment)
                    if theme:
                        theme_counts[theme].append(moment)

        for theme, occurrences in theme_counts.items():
            if len(occurrences) >= MIN_PATTERN_THRESHOLD:
                confidence = self.calculate_confidence(occurrences, len(user_analyses))
                patterns.append(Pattern(
                    type='tactical', subtype=theme,
                    occurrences=len(occurrences),
                    confidence=confidence, examples=occurrences[:5]
                ))
        return patterns

Positional Pattern Detector

python
class PositionalPatternDetector:
    def detect(self, user_analyses: List[GameAnalysis]) -> List[Pattern]:
        patterns = []

        # Analyze by position type (open/closed, IQP, etc.)
        position_performance = defaultdict(lambda: {'wins': 0, 'losses': 0, 'acpl': []})

        for analysis in user_analyses:
            pos_type = self.classify_position_type(analysis)
            game_result = analysis.game.result

            position_performance[pos_type]['wins'] += game_result == 'win'
            position_performance[pos_type]['losses'] += game_result == 'loss'
            position_performance[pos_type]['acpl'].append(analysis.acpl)

        # Detect position-specific weaknesses
        for pos_type, stats in position_performance.items():
            win_rate = stats['wins'] / (stats['wins'] + stats['losses'] + 0.001)
            avg_acpl = mean(stats['acpl'])

            if win_rate < 0.4 and len(stats['acpl']) >= MIN_GAMES:
                patterns.append(Pattern(
                    type='positional',
                    subtype=f'struggles_in_{pos_type}',
                    win_rate=win_rate,
                    avg_acpl=avg_acpl
                ))

        return patterns

Opening Pattern Detector

python
class OpeningPatternDetector:
    def detect(self, user_analyses: List[GameAnalysis]) -> List[Pattern]:
        opening_performance = defaultdict(lambda: {'games': [], 'results': []})

        for analysis in user_analyses:
            eco = analysis.opening_eco
            opening_performance[eco]['games'].append(analysis)
            opening_performance[eco]['results'].append(analysis.game.result)

        for eco, data in opening_performance.items():
            games, results = data['games'], data['results']
            if len(games) >= MIN_OPENING_GAMES:
                win_rate = results.count('win') / len(results)
                if win_rate < 0.35:
                    yield Pattern(type='opening', subtype=eco,
                                  win_rate=win_rate, is_strength=False)
                elif win_rate > 0.7:
                    yield Pattern(type='opening', subtype=eco,
                                  win_rate=win_rate, is_strength=True)

7.3 Pattern Scoring Algorithm

Confidence combines three factors:

  • Sample size — more occurrences (and more games) mean higher confidence.
  • Prevalence — how much of the analysed history the pattern touches.
  • Recency — recently seen patterns are weighted higher.
python
def calculate_pattern_confidence(
    occurrences: int, total_games: int, last_seen_days: int = None
) -> float:
    sample_confidence = min(occurrences / 10, 1.0)
    prevalence_score  = min((occurrences / total_games) * 3, 1.0)

    recency_multiplier = 1.0
    if last_seen_days:
        if last_seen_days > 90: recency_multiplier = 0.5
        elif last_seen_days > 30: recency_multiplier = 0.8

    return round(
        (sample_confidence * 0.4 + prevalence_score * 0.6) * recency_multiplier, 2
    )

Move Timing & Behavioral Analysis NEW

8.1 Time Data Extraction

python
class MoveTimingExtractor:
    def extract_from_pgn(self, pgn: str, user_color: str) -> List[MoveTiming]:
        game = chess.pgn.read_game(io.StringIO(pgn))
        timings = []
        prev_clock = None

        for move_number, node in enumerate(game.mainline(), start=1):
            clock_str = node.clock()
            if clock_str is not None:
                clock_remaining = self.parse_clock(clock_str)
                think_time = (prev_clock - clock_remaining) if prev_clock else None
                phase = self.determine_phase(move_number, node.board())
                time_pressure = self.is_time_pressure(clock_remaining, game.time_control)

                timings.append(MoveTiming(
                    move_number=move_number,
                    think_time_seconds=think_time,
                    clock_remaining_seconds=clock_remaining,
                    time_pressure=time_pressure,
                    phase=phase
                ))
                prev_clock = clock_remaining
        return timings

8.2 Behavioral Pattern Detection

python
class TimingPatternDetector:
    def detect(self, user_timings: List[MoveTiming]) -> TimingPatterns:
        patterns = TimingPatterns()

        long_thinks   = [t for t in user_timings if t.think_time_seconds > 120]
        quick_moves   = [t for t in user_timings
                         if t.think_time_seconds < 5 and not t.is_book_move]
        pressure_moves = [t for t in user_timings if t.time_pressure]

        patterns.overthink_tendency   = len(long_thinks)    / len(user_timings)
        patterns.impulsive_tendency   = len(quick_moves)    / len(user_timings)
        patterns.time_pressure_ratio  = len(pressure_moves) / len(user_timings)

        phase_times = defaultdict(list)
        for t in user_timings:
            phase_times[t.phase].append(t.think_time_seconds)

        patterns.phase_time_distribution = {
            phase: mean(times) for phase, times in phase_times.items()
        }
        return patterns

class CoachContextAssembler:
    def assemble_context(self, user_id, user_message, conversation_history):
        context = CoachContext()
        context.player_profile = self.db.get_player_profile(user_id)
        all_patterns = self.db.get_player_patterns(user_id)
        context.relevant_patterns = self.filter_patterns_by_query(all_patterns, user_message)

        if self.is_game_specific_query(user_message):
            context.recent_games = self.db.get_recent_analyses(user_id, limit=10)

        context.conversation_history = conversation_history[-5:]
        context.query_type = self.classify_query(user_message)
        return context

10.2 Pattern-Based Recommendation Generation

Recommendations are generated primarily from the patterns detected in player_patterns, not just from raw game statistics.

Priority order: Critical patterns → Significant patterns → Strength building

python
def build_recommendations_from_patterns(patterns, profile):
    sorted_patterns = sorted(
        patterns, key=lambda p: (p.severity != 'critical', -p.confidence_score)
    )
    recs = []
    for pattern in sorted_patterns[:7]:
        if pattern.is_strength:
            rec = Recommendation(
                category=f"Leverage Your {pattern.pattern_type.title()} Strength",
                title=f"You're strong at {pattern.pattern_subtype}",
                severity="positive", recommendation_type="strength_building",
                confidence=pattern.confidence_score
            )
        else:
            rec = Recommendation(
                category=pattern.pattern_type.title(),
                title=f"Work on {pattern.pattern_subtype}",
                severity=pattern.severity, recommendation_type="weakness_correction",
                drill_type=pattern.recommended_drill_type,
                confidence=pattern.confidence_score
            )
        recs.append(rec)
    return recs

12.2 AI Coach APIs

POST /api/v1/chat/session

Creates a coaching session in one of three conversation modes. Each mode runs the same grounded base prompt plus a mode-specific rule set, so the conversation shape matches the user intent.

POST /api/v1/chat/message

Routes the user message through intent classification. Every analytic intent receives assembled grounding (player context, patterns, semantic memories, Conversation Record); the LLM prompt carries three mode-specific rule layers:

  • Coach (default) — grounded base prompt: answer the question directly, never compute or invent engine evaluations, recall honesty (answer from records or say plainly there is no record).
  • Interview — 4-essentials structured intake (rating goal, weakness, weekly time budget, openings); when complete the model appends an [INTERVIEW_SUMMARY] block, which the parser strips from the visible reply and persists into the memory layer idempotently.
  • Analyze — technical position replies built only from the engine facts section; when no engine facts are present the model asks for a FEN rather than estimating an evaluation.

Substrate Refinements

The sections above describe the engine pass and its consumers. The substrate underneath them has since been made explicit, so that every claim the coach makes can be traced back to one engine evaluation of one move. The full record lives in Player Intelligence Architecture.

LayerRefinement
Move factsOne row per ply: position identity, structure key, material balance, phase, the mover's own cp_loss, and the engine's best move for the position the mover actually faced
Chess eventsThe decisions that mattered, detected deterministically behind a minimum-opportunity gate — no model involved
PatternsOccurrence-backed: each pattern carries the games, plies and engine evidence behind it
Player modelLongitudinal profile built from analysis rows and patterns, with behavioural hypotheses derived from decisions rather than self-report
RetrievalSimilar historical games and decisions surface precedent for the position under discussion
Coaching contextRanked evidence assembled per question; pattern claims reach the model without severity vocabulary it should never repeat
EvaluationProbe-based harness scoring grounding, pattern assertions and engine-vocabulary leakage against the real coach prompt — the gate that decides whether fine-tuning is justified at all

Corrections that changed what the player sees

  • Accuracy and ACPL. Both were derived from evaluations compared across opposite frames (§4.2.3), which inflated ACPL roughly fourfold — up to thirty-fivefold in the worst game — and reported single-digit accuracy for games that were played well. The metric is now the mover-frame loss, and stored analyses were rebuilt from the move-facts layer without re-running the engine.
  • Honest counts. A Chess.com record stored without a single move (an aborted game) can never be analysed. It is now excluded from the queue, never retried, and reported separately, instead of silently shrinking the analysed count on screen.
  • Liveness versus readiness. The endpoint that decides whether an instance stays alive no longer probes Postgres or Redis. Dependency checks moved to a separate readiness path, so a slow dependency can no longer evict a healthy instance and break every in-flight request.
