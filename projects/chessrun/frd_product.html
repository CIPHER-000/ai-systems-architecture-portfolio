Product Overview

1.1 Vision

ChessRun is an AI-powered personalized chess intelligence and coaching platform that transforms how players improve at chess. Unlike traditional game analyzers that provide one-off engine evaluations, ChessRun builds a comprehensive understanding of each player's unique patterns, tendencies, and developmental needs across their entire game history.

More precisely, ChessRun is an AI chess coach that uses game analysis to personalize coaching conversations. It builds a concise Playing Profile from a player's games and uses that context to guide a persistent coaching conversation.

MVP direction

CHESSRUN_MVP_UX.md is the canonical product definition for the current launch scope. ChessRun is an AI chess coach whose primary interface is conversation. Dashboard, report, and training-mode concepts in this FRD are future-facing unless explicitly described in the MVP UX document.

ChessRun Is NOTChessRun IS
Just a game analyzerA personalized AI chess coach that learns your unique playing style
Just a Stockfish wrapperA behavioral pattern recognition system identifying recurring tendencies across hundreds of games
Just a dashboard for metricsA conversational chess intelligence platform where players ask questions and receive contextual, personalized guidance

The key differentiator is long-term pattern recognition: The AI learns recurring patterns across a player's games and provides personalized coaching based on those longitudinal insights, not just individual game analysis.

Target users: Intermediate online players (~1000–2200 Elo) seeking personalized, actionable coaching that evolves with their play.

1.2 High-Level Capabilities

Core Platform

  • Chess.com account linking by username (no OAuth in MVP)
  • Game fetching with filters: count, time control, rated/unrated, date range
  • Chess.com is the external source of truth for raw game data (PGNs, move history, ratings, timestamps)
  • Lightweight game storage — recently fetched games are temporarily cached; Stockfish analysis outputs and detected patterns are stored permanently
  • Batch analysis of games using Stockfish via Celery workers
  • Move timing and clock data ingestion for behavioral analysis
  • Analysis depth advantage: ChessRun's free-tier analysis depth may exceed Chess.com's free analysis, framed as deeper analysis + personalized coaching + longitudinal intelligence

Pattern Recognition Engine

  • Long-term behavioral pattern detection across hundreds of games
  • Recurring mistake identification in similar positions
  • Opening-specific weakness detection, middlegame collapse patterns, tactical recurrence
  • Endgame weakness profiling, strategic habit detection
  • Time management issue identification, hesitation/overthinking detection
  • Impulsive play pattern recognition and longitudinal player profile generation

AI Coach / Conversational Interface

  • Natural language Q&A about player patterns and games
  • Personalized improvement recommendations and context-aware coaching
  • Conversational exploration of player strengths and weaknesses
  • Persistent coaching threads where prior context can be restored
  • Pattern-aware starter suggestions and follow-up questions
  • Interactive drill and study suggestions

Playing Profile

  • Collapsible coaching context panel
  • Games analyzed
  • Patterns identified
  • Strongest area
  • Biggest bottleneck
  • Last analysis timestamp

Future Training Mode

  • Pattern-specific drills based on recurring weaknesses
  • Critical moment replay with coaching context
  • Personalized study plans based on pattern analysis

User Roles & Personas

2.1 Roles

  • Player (End User) — Owns a profile, links Chess.com username, fetches games, runs analyses, consumes recommendations and training drills
  • Admin / Support — Inspects user stats and logs, triggers re-analysis, adjusts system-wide settings
  • System / Background Workers — Celery workers performing heavy engine analysis and generating insights

2.2 Primary User Journeys

First-Time Setup

  1. Enters Chess.com username and email
  2. ChessRun creates or finds user
  3. User chooses filters (e.g., last 25 rapid rated games)
  4. Games fetched, stored, and visible on dashboard as "Not analyzed"
  5. User clicks "Analyze All Games" to start analysis

Return Visit

  1. Lands directly on /dashboard?username=…
  2. Sees summary of performance and last analyzed period
  3. Can sync new games, re-analyze, or enter Training Mode
MVP journey direction

In the current MVP direction the first-time flow is: enter a Chess.com or Lichess username, click Start Coaching, and land directly in the AI Coaching Interface. The coach welcomes the user and explains that game analysis can build a personalized Playing Profile; the user opens the Analyze Games modal, selects a timeframe, and analysis runs in the background while the conversation remains available. When analysis completes, the Playing Profile updates and the coach starts a personalized coaching conversation around one high-impact pattern.

  • Returning players land directly in the coaching workspace.
  • They can start a new chat or reopen previous coaching conversations from the sidebar.
  • They can reopen Analyze Games from the sidebar or mobile menu.
  • The Playing Profile remains persistent and collapsible.

Functional Requirements

3.1 Authentication & Identity

FR-AUTH-1
Users authenticate via lightweight account (email + Chess.com username). No password in MVP.
FR-AUTH-2
System uniquely identifies users by lowercase chesscom_username.
FR-AUTH-3
On first login: If user exists → "Welcome back". Else → create Supabase users row with username, display name, email, timestamps.

3.2 Game Fetching

3.2.1 Filters & Options

FR-GAMES-1
User can choose: game_count (10, 25, 50, 100), time_controls (rapid, blitz, bullet, daily), rated_filter (rated, unrated, both), optional start_date/end_date.

3.2.2 Behavior

FR-GAMES-2
On new fetch, app uses replace all semantics: remove or logically archive prior games within scope. Chess.com is the external source of truth; ChessRun maintains only the working cache needed for active analysis and coaching.
FR-GAMES-3
"Get Started" flow: Find/create user → POST games/fetch with filters → show progress → toast fetched count → redirect to /dashboard.
FR-GAMES-4
Backend ensures idempotent storage (no duplicate games per user_id + external game id).

3.3 Coaching Workspace — Analyze Games

Analysis is requested from inside the coaching workspace. Analyze Games opens as a modal over the conversation, so the chat stays the primary surface and the user is never taken away from it.

FR-ANALYZE-1
Analyze Games is always a modal overlay, never a standalone page.
FR-ANALYZE-2
The modal offers:
  • Last 7 Days
  • Last 30 Days
  • This Month
  • Analyze All Games
  • Custom Range
FR-ANALYZE-3
Click Analyze Games to open the modal. Click Cancel or outside the modal to close it. Clicking Analyze Games again reopens it.
FR-ANALYZE-4
Desktop keeps Analyze Games visible in the sidebar. Mobile exposes it through a menu or sync action.

3.4 Playing Profile

The Playing Profile is the collapsible coaching-context panel of the coaching workspace. It is what the coach reads from and what the player can always check: a concise, persistent summary of the player, deliberately written as a scouting report rather than a statistics dashboard.

FR-PROFILE-1
Rename Player Intelligence Profile to Playing Profile.
FR-PROFILE-2
Playing Profile is persistent across coaching sessions and collapsible in the coaching workspace.
FR-PROFILE-3
Playing Profile summarizes:
  • Games Analyzed
  • Patterns Identified
  • Strongest Area
  • Biggest Bottleneck
  • Last Analysis Timestamp
FR-PROFILE-4
Playing Profile should read like a coach's scouting report, not a statistics dashboard.

3.5 Coaching / Recommendations

FR-COACH-1
Coaching Insights panel lists 3–7 key insights with: Category, Headline, Description, Severity level (low/medium/high), Recommended drill type.
FR-COACH-2
Insights derived from: repeated blunders in similar positions, high ACPL or low accuracy in specific phases, particular tactical themes frequently missed.

3.5.1 Weekly Coaching Loop

FR-DIGEST-1
Every week (automatically, post-analysis), the coach compiles a digest of what changed and what deserves focus, grounded in that week's pattern facts and drills completed.
FR-DIGEST-2
Digests surface in-app in the Weekly Coaching Loop feed with unread state and mark-as-read; email delivery is optional and separately controlled.
FR-DIGEST-3
The loop closes: digest → focus areas → coach-authored drills → next week's digest reports on drill completion.

3.6 Analysis Workflow

FR-WORKFLOW-1
"Analyze All Games" → frontend calls backend endpoint → backend queues Celery jobs for unanalyzed games → frontend shows modal with queued count.
FR-WORKFLOW-2
Frontend periodically polls summary/games status until all queued games show is_analyzed = true or timeout/max polling hits.
FR-WORKFLOW-3
On completion: modal closes, dashboard summary and game list update, toast notification fires.

In the MVP direction, completion also refreshes the Playing Profile automatically and the coach sends a conversational follow-up focused on one high-impact pattern — the conversation, not a report screen, remains the primary surface for interpreting the results.

FR-WORKFLOW-4
"Re-analyze" button for advanced users forces recompute of previously analyzed games.

3.6.1 Auto-Analysis (Premium Feature)

Auto-analysis is the always-on form of the workflow above: once a Pro/Elite user opts in, ChessRun keeps fetching, analyzing and profiling in the background without a manual click.

FR-WORKFLOW-5
Premium Pro/Elite users can enable automatic background analysis: periodic Chess.com game fetching, auto-queue for Stockfish, incremental profile updates.
FR-WORKFLOW-6
Premium Auto-analysis generates scheduled reports (daily/weekly coaching summary) delivered as in-app notifications and optionally via email.
  • Fetch interval: recent Chess.com games are pulled on a configurable schedule — for example daily or weekly
  • Automatic pattern pass: pattern recognition runs as soon as analysis completes, and the player profile is updated incrementally
  • Digest contents: newly detected patterns, accuracy trends, and opening performance changes
  • Purpose: drive retention, maintain habit loops, and keep AI memory continuously updated without requiring manual user action
Non-MVP note

Scheduled reports are future-facing. The MVP should keep analysis output inside coaching conversations.

3.7 Future Training Mode

Training Mode turns detected patterns into practice. It is not part of the ChessRun MVP: the backend and domain ideas are preserved for future planning, but drill UX and the training-plan lifecycle do not block launch.

FR-TRAIN-0
Training mode is not part of the ChessRun MVP. Preserve backend/domain ideas for future planning, but do not block MVP launch on drill UX or training-plan lifecycle.
FR-TRAIN-1
In a future release, the user can enter Training Mode from:
  • Game row ("Train this game")
  • Insight card ("Practice rook endgames")
FR-TRAIN-2
Training mode includes:
  • Interactive board
  • Move list
  • Engine evaluation bar (optional for MVP)
FR-TRAIN-3
Drill behavior for critical moments:
  • Board shows the position just before the user's mistake
  • The user is prompted to choose the best move
  • On a correct move: show confirmation and explanation, then proceed
  • On an incorrect move: show feedback and the engine's best move, then allow a retry
FR-TRAIN-4
Training stats: track the number of drills attempted and the success rate by theme.

3.7.1 Training Artifacts

FR-TRAINART-1
The coach (in Coach or Interview mode) saves drills and training plans focused on the player's detected patterns; everything saved surfaces in the player's Training collection.
FR-TRAINART-2
Active plan view: title, focus areas (from the interview baseline and pattern profile), and a progress bar over the plan's drill set.
FR-TRAINART-3
Drill workflow: start a drill, record the attempt (optional answer, solved / missed), or skip; plan counters sync automatically and plans complete when their drills do.
FR-TRAINART-4
Progress rollups: all-time attempts and success by drill type, plus per-plan completion — the coach uses the same data to adjust future plans.

3.8 Pattern Recognition Engine

The Pattern Recognition Engine is the intelligence layer that transforms individual game analyses into personalized coaching insights. It operates on the principle of longitudinal analysis — identifying recurring patterns across many games.

3.8.1 Pattern Detection Categories

FR-PATTERN-1
Recurring Positional Mistakes — Detect when user repeatedly blunders in similar position types. E.g.: "You have blundered material in 8 out of 15 King's Gambit middlegame positions with this pawn structure."
FR-PATTERN-2
Opening-Specific Weaknesses — Track performance by opening/repertoire line. E.g.: "You lose 73% of games when playing the Sicilian Dragon."
FR-PATTERN-3
Middlegame Collapse Patterns — Identify at-risk transition points. E.g.: "You consistently lose positional battles around moves 18-25."
FR-PATTERN-4
Tactical Recurrence — Frequently missed tactical themes (forks, skewers, pins). E.g.: "You've missed knight forks in similar positions 14 times in the last 50 games."
FR-PATTERN-5
Endgame Weaknesses — Recurring technique failures. E.g.: "You have drawn 6 winning rook endgames this month."
FR-PATTERN-6
Strategic Habits — Positional vs. tactical tendencies. E.g.: "You perform better in closed positions (62% win rate) vs. open positions (41% win rate)."
FR-PATTERN-7
Castling & King Safety — Delayed castling risks. E.g.: "Your win rate drops to 28% when you lose castling rights before move 15."
FR-PATTERN-8
Strong Recurring Patterns (Strengths) — Positions where user consistently excels. E.g.: "You have a 78% success rate in IQP positions."

3.8.2 Pattern Scoring & Severity

FR-PATTERN-9
Severity Levels: Critical >30% of relevant games, high impact · Significant 15–30% of relevant games · Developing <15% of games · Historical detected but improving
FR-PATTERN-10
Confidence Scoring — Based on: sample size (games analyzed), statistical significance, recency weighting.

3.8.3 Longitudinal Player Profile

FR-PATTERN-11
Player Archetype Generation — System generates a "player archetype" combining strengths, weaknesses, and stylistic tendencies. Examples: "The Tactician with Endgame Blind Spots", "The Solid Builder with Opening Gaps", "The Time Pressure Panicker".
FR-PATTERN-12
Evolution Tracking — Track how patterns change over time; surface "breakthrough" moments; identify persistent vs. resolved weaknesses.

3.9 Move Timing & Clock Data Analysis

ChessRun analyzes not just what moves were played, but how time was used — revealing behavioral patterns invisible to traditional engine analysis.

3.9.1 Time Data Ingestion

FR-TIMING-1
Clock Data Capture — Ingest move timestamps from Chess.com PGNs; calculate think time per move; store clock remaining; track time spent by phase.
FR-TIMING-2
Time Pressure Detection — Identify moves under time pressure (<30s blitz, <2min rapid); flag "panic moves"; correlate with move quality.

3.9.2 Behavioral Pattern Detection

FR-TIMING-3
Overthinking Patterns — Detect excessive think time followed by blunders. E.g.: "You spent 3+ minutes on 8 positions and blundered in 6."
FR-TIMING-4
Impulsive Play Detection — Flag moves played too quickly given position complexity. E.g.: "You blundered on 12 moves played in under 5 seconds when you had plenty of time."
FR-TIMING-5
Time Management Collapse — Games where user burned time early and collapsed in endgame. E.g.: "You consistently reach the endgame with <30 seconds and make 3× more errors."
FR-TIMING-6
Hesitation Patterns — Recurring hesitation on specific position types; confidence patterns; improvement in decision speed over time.

3.9.3 Time-Based Recommendations

FR-TIMING-7
Personalized Time Management Coaching — Recommend time allocation strategies; suggest thinking heuristics; flag opening lines where user consistently overspends.

3.10 AI Coach / Conversational Interface

The AI Coach is a primary interface of ChessRun — not an add-on, but a core way users interact with their chess intelligence.

The coach should never dump analysis results. It should identify one high-impact improvement opportunity and begin a conversation around it.

Three Conversation Modes

Every coaching conversation runs in one of three modes, selected when the conversation starts:

FR-AICOACH-0a
Coach mode (default) — grounded improvement conversation about the player's patterns, games, and goals.
FR-AICOACH-0b
Analyze mode — position-focused technical analysis; the user pastes a FEN and receives an answer built only on engine facts, never an estimated evaluation.
FR-AICOACH-0b
Interview mode — a structured baseline intake: the coach asks short, single questions covering the rating goal, the self-perceived weakness, the weekly time budget, and the openings; the completed profile is saved to the coach's memory and becomes the player's focus areas. The interview never invents facts to fill a gap.

3.10.1 Conversational Capabilities

FR-AICOACH-1
Pattern-Based Questions — "Why do I keep blundering in the middlegame?", "What openings fit my style?", "How has my play changed over the last 3 months?"
FR-AICOACH-2
Specific Game Questions — "Why was move 18 a mistake?", "Was I winning at any point?", "Why did I spend 5 minutes and still blunder here?"
FR-AICOACH-3
Comparative Analysis — "How does my blitz compare to rapid?", "Do I play better as White or Black?", "Am I improving in tactics?"
FR-AICOACH-4
Improvement Planning — "Create a training plan for my endgame weaknesses", "Recommend drills for my knight fork problem."
FR-AICOACH-5
Opening & Repertoire Guidance — "What opening should I play against 1.e4?", "Is the Sicilian right for me?"

3.10.2 AI Coach Intelligence Requirements

FR-AICOACH-6
Context-Aware Responses — Must reference the player's actual patterns and data; include specific examples from the player's games; avoid generic advice.
FR-AICOACH-7
Multi-Source Intelligence — Synthesizes: Pattern Engine outputs, Stockfish findings, historical game trends, time management patterns, phase-based performance.
FR-AICOACH-8
Conversational Memory — Persistent memory across sessions: every coaching conversation writes pattern facts and interview summaries into the coach's memory store, retrievable later and visible to the player ("What your coach knows"). The coach maintains rolling thread summaries so long conversations retain context without silent truncation.
FR-AICOACH-9
Actionable Recommendations — Specific and actionable; drills the coach saves surface in the Training artifact collection with plan progress tracking.
FR-AICOACH-12
Recall Honesty — When asked what was discussed before, the coach answers only from its records; if something is absent it says so plainly rather than inventing it.

3.10.3 Explanation Quality

FR-AICOACH-10
Human-Readable Explanations — Conversational language (not notation-heavy); analogies and conceptual explanations; depth adapted to user skill level.
FR-AICOACH-11
Evidence-Based Coaching — Cite specific evidence ("In 12 similar positions…"); show statistics; reference patterns by confidence level.

Non-Functional Requirements

4.1 Performance

  • Single batch analysis of ~25 rapid games: typically complete within 2–5 minutes under normal load
  • Dashboard load time (summary + games): under 1.5 seconds P95 on typical broadband
  • Coaching workspace initial load (conversation shell + Playing Profile summary): under 1.5 seconds P95 on a typical broadband connection

4.2 Scalability

  • 10K+ registered users
  • 1M+ games stored
  • Dozens of concurrent analysis jobs handled by Celery workers

4.3 Reliability & Resilience

  • Chess.com API unavailable: show human-readable error, suggest retry, enforce backend timeouts
  • Individual game analysis failure: mark analysis_failed, continue others, surface minimal error in logs only

4.4 Security & Privacy

  • No user passwords stored (MVP uses username + email only)
  • All database connections over TLS (Supabase)
  • User PGNs and analysis data are private and not visible to other users
  • API endpoints protected: rate limiting, payload size limits

UX & Interaction Notes

5.1 Landing Page

  • Clear value prop explanation
  • Simple form: Chess.com username, email, filters (count, time control, rated)
  • Username may be a Chess.com or Lichess username
  • Primary CTA: "Get Started"
  • CTA label in the MVP direction: "Start Coaching"
  • On submit, the user is routed directly into the AI Coaching Interface
  • Inline status messages: "Creating account…", "Fetching your games…"

5.2 Coaching Workspace Layout

Desktop behaves similarly to ChatGPT: the conversation is the primary workspace, and everything else supports it.

Recommended layout:

  1. Sidebar
    • New Chat
    • Conversation History
    • Analyze Games in the bottom section
  2. Conversation Workspace
    • Persistent chat thread
    • Coach welcome and pattern-aware follow-ups
    • Message composer fixed near the bottom
  3. Playing Profile
    • Collapsible context panel
    • Collapsed by default on smaller screens
    • Summarizes coaching context rather than detailed analytics
  4. Analyze Games Modal
    • Opens over the coaching workspace
    • Offers the fixed timeframe choices and a custom range
    • Does not take the user away from the conversation

5.3 Empty States

  • No games fetched: CTA to go back to landing or "Fetch your first games" button
    • Coach explains that analyzing games will build a personalized Playing Profile
    • Show Analyze Games as the primary next action inside the coaching workspace
  • No analysis yet: Explanation and prominent "Analyze All Games" button
    • Keep the coach conversational and invite the user to analyze recent games
    • Avoid empty analytics panels

5.4 Dashboard Layout (Recommended Order)

The dashboard ordering below is the report-style alternative to the coaching workspace layout in 5.2.

  1. Top Bar — Greeting, username, quick navigation
  2. AI Coach Widget — Quick-access chat, recent conversation snippets, pattern alerts: "New insight: You struggle with rook endgames"
  3. Key Metrics / Performance Cards — Overall accuracy, ACPL, Win rate, Time management score
  4. Pattern Recognition Panel — Player archetype summary, top 3–5 recurring patterns, evolution indicators
  5. Move Quality / Phase Charts
  6. Coaching Insights — Pattern-driven, severity-ranked with drill links
  7. Time Management Insights — Time usage visualization, overthinking/impulsive alerts
  8. Fetched Games (collapsible)
